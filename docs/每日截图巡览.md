# 每日截图巡览：每天 5 分钟看 12 张图

> 适用阶段：P2–P5 ｜ 何时加载：每天收工、每周五验收 ｜ 上游：可运行构建 + 当天截图 ｜ 下游：交付单证据、D3 验收、周报
>
> 一句话：把当天的 UE 截图按日期整理成一页 HTML，你每天花 5 分钟翻 12 张图，用 3 条判据决定“继续 / 返工 / 进验收”。

## 为什么需要截图巡览

没有巡览时，agent 每天在交付单里写“完成”，你周五才发现方向错了，返工 3 天。
有巡览时，你每天花 5 分钟看到 12 张实际画面，问题在第 1 天就被拦住。

| 维度 | 没有巡览 | 有巡览 |
|---|---|---|
| 发现问题的时机 | 周五验收或集成时 | 当天收工前 |
| 你投入的时间 | 周五 2–3 小时集中补看 | 每天 5 分钟 × 5 天 = 25 分钟 |
| 返工成本 | 1 天以上 | 通常 ≤1 个任务 |
| 证据留存 | 口头“做完了” | 按日期归档的图片 + 交付单引用 |
| 与 D3 验收的关系 | 只能凭印象签字 | 打开 index.html 逐张核对 |

### 正例【示例】

周四收工，agent 生成当日巡览，你打开 `docs/gallery/index.html`：

- 12 张图里，第 7 张的台阶高 1.1 m，角色跳跃高度 2.2 m，落点悬空；
- 你在交付单写“问题 3：L02 台阶与跳跃参数不匹配”，并附该图相对路径；
- 周五任务先修这一项，不改其他内容。

### 反例

- 交付单只写“关卡已完成”，没有任何截图路径 → 直接退回，不算交付；
- 每天截 80 张图但从不整理 → 周五无法定位改动前后的差异；
- 截图放在桌面，第二天被覆盖或删掉 → 没有可追溯证据。

## 每天看哪 12 张图

固定 12 张，不按心情增减。1 张总览 + 3 张空间 + 3 张玩法 + 3 张资产/UI + 2 张问题记录。

| 阶段 | 12 张的配额 | 3 秒判据 |
|---|---|---|
| P2 白模 | 1 总览 + 4 跳跃点 + 4 战斗点 + 3 关键门洞 | 空间可读、落点明确、门高 ≈1.2 个角色高 |
| P3 垂直切片 | 1 总览 + 3 新资产 + 1 光照锚点 + 4 关卡流程 + 3 问题对比 | 新资产与锚点同框不跳风格、无粉材质 |
| P4 内容生产 | 1 总览 + 5 关卡关键帧 + 3 敌兵 + 3 UI/交互 | 每个关卡目标在画面里能指出来 |
| P5 打磨上线 | 1 总览 + 3 性能场景 + 3 UI + 3 商店候选 + 2 问题对比 | 1080p 下无糊字、无穿模、无闪烁 |

### 5 分钟计时

| 时间 | 动作 | 停下来的条件 |
|---|---|---|
| 0:00–1:00 | 打开 `index.html`，看总张数与日期 | 当天张数 <12，补齐再继续 |
| 1:00–3:00 | 从上到下翻 12 张，只看大形状与光照方向 | 发现 1 个“明显不对”，立刻记下文件名 |
| 3:00–4:00 | 用 `--compare` 对比昨天与今天 | 同机位画面差异无法解释 |
| 4:00–5:00 | 把问题写进交付单或测试记录，附图片路径 | 写不出可复现位置 = 问题描述不合格 |

3 秒判据只有三条，不要扩展：

1. **能不能看出这是什么地方**：入口、出口、可走面在画面里能区分；
2. **有没有出现禁止项**：粉材质、穿模、悬空、贴图接缝、UI 糊字；
3. **和昨天比是否更接近标准**：同机位对比，没有变化的“优化”不算完成。

## UE 里怎么截图

三种方法按成本排序。每天 12 张用方法一；固定机位回归用方法二；每天 1–2 张高质量关键帧用方法三。

### 方法一：标准截图 / 高清截图（每天主力）

1. 在编辑器 PIE 或独立运行中进入要记录的机位。
2. 按 **F9**（默认绑定控制台命令 `Shot`）截当前窗口分辨率。
3. 需要固定分辨率时，按 `~` 打开控制台，输入：

```text
HighResShot 1920x1080
HighResShot 3840x2160
HighResShot 1920x1080 filename="P2_L02_003_jump"
```

4. 默认保存目录是项目下的 `Saved\Screenshots\Windows`（以官方文档为准）。

| 做法 | 结果 |
|---|---|
| 每天固定 1920×1080、同一 FOV、同一后处理 | 与昨天 `--compare` 有效 |
| 一天 1080p、一天 4K，帧率与机型混用 | 对比失效，只能当单张记录 |
| 用 `bCaptureHDR` 输出 `.exr` | 浏览器不能直接显示，不要放进巡览 |

- 官方文档：[Taking Screenshots in Unreal Engine](https://dev.epicgames.com/documentation/unreal-engine/taking-screenshots-in-unreal-engine)
- 说明：UE5 控制台命令是 `HighResShot`；部分旧教程写作 `HighResScreenshot`，以你所装版本的自动补全为准。

### 方法二：Automation 自动跑固定机位（回归用）

适用：P2 之后每天要在同一批机位截同样的图；手工摆相机 12 次超过 5 分钟。

1. 打开 **Session Frontend > Automation**，确认 Automation 测试能列出。
2. 写一个 Editor 或 Functional Test：固定相机 Transform 与前处理，调用自动化截图函数（Blueprint 节点 `Take Automation Screenshot`；C++ 在 `UAutomationBlueprintFunctionLibrary` 内，函数名以版本内自动补全为准）。
3. 用控制台 `Automation RunTests <测试名>` 运行；截图产物落在 `Saved/Screenshots` 下。
4. 把测试名、截图目录、生成日期写进 `docs/10_测试记录.md`。

| 约束 | 原因 |
|---|---|
| 机位与 FOV 写死在测试里 | 保证每天对比的是同一画面 |
| 每个机位只截 1 张 | 12 张配额不允许自动跑出 200 张 |
| 截图 API 只用于编辑器/开发构建 | Shipping 包不依赖自动化截图 |
| 测试失败也要保留截图 | 失败画面就是缺陷证据 |

- 官方文档：[Automation Test Framework](https://dev.epicgames.com/documentation/unreal-engine/automation-test-framework-in-unreal-engine)
- 截图函数签名与参数以官方 API 页与编辑器自动补全为准，不要硬编码教程里的旧版参数。

### 方法三：Movie Render Queue（每天 1–2 张关键帧）

适用：需要干净抗锯齿与稳定光照的关键帧；不适合每天 12 张全用（离线渲染成本高）。

1. `Edit > Plugins` 启用 **Movie Render Queue**，重启编辑器。
2. 打开 `Window > Cinematics > Movie Render Queue`，`+ Render` 添加 Level Sequence。
3. `Settings > + Setting > Export` 选 **.png Sequence [8bit]**。
4. 在 `Output` 设置里把 **Output Directory** 指到 `Saved/Screenshots/<日期>/`，输出格式保持 PNG。
5. 只渲染需要的 1–2 帧（缩短序列或收窄帧范围），点 **Render**。
6. 对 `Saved/Screenshots` 跑生成命令；父目录 `2026-11-14` 会被优先当成日期。

| 做法 | 结果 |
|---|---|
| MRQ 输出 PNG，目录名是日期 | 分组稳定，不依赖 mtime |
| 输出 `.exr` / `.bmp` | 浏览器显示不了，巡览页会破图 |
| 每天渲染整段 30 秒视频 | 单次几十 GB，超过每日证据需要 |

- 官方文档：[Movie Render Pipeline](https://dev.epicgames.com/documentation/unreal-engine/movie-render-pipeline-in-unreal-engine)
- 输出格式说明：[Cinematic Rendering Export Formats](https://dev.epicgames.com/documentation/unreal-engine/cinematic-rendering-export-formats-in-unreal-engine)

### 文件名与目录

两条路线，选一条并每天照做。

| 路线 | 做法 | 日期来源 | 适用 |
|---|---|---|---|
| A 直接用 UE 默认目录 | `--src Saved/Screenshots`，不复制、不移动 | 文件 mtime 的本地日期 | 每天手工截图 |
| B 日期父目录 | 把图片放进 `Saved/Screenshots/2026-11-14/` | 父目录名 | 自动跑图、归档、跨设备 |

文件名规则：`P<阶段>_<关卡或系统>_<三位序号>_<英文短说明>.png`。

- 正例【示例】：`P2_L02_003_jump.png`、`P3_env_ruins_001_wall.png`、`P5_ui_004_settings.png`
- 反例：`无标题.png`、`截图 (12).png`、`1.png`、`新建文件夹/a.png`

不要做的事：

- 不要用 `Windows` 当日期父目录，它不是合法 `YYYY-MM-DD`，脚本会回退到 mtime；
- 不要用 `2026.11.14`、`2026-11-14 周一` 这类目录名，日期解析会失败；
- 不要把原图反复复制到多个日期目录，同一张图会在巡览里出现多次。

## 生成巡览：一条命令

### 前置条件

- Python 3.10 及以上；只用标准库，不安装第三方包。
- 脚本在 skill 仓库的 `scripts/daily_gallery.py`。游戏项目里把它复制到项目自己的 `scripts/`（与 `gamecheck.py` 同级），之后命令不依赖 skill 安装路径。
- 在仓库根或项目根执行；相对路径按当前目录解析。Windows 路径含空格时用双引号包住。

### 命令模板

```powershell
# 最简单的每日巡览（输出到 当前目录/gallery）
python scripts/daily_gallery.py --src "D:/Game/Saved/Screenshots"

# 指定输出目录与标题（推荐：写进项目 docs/gallery）
python scripts/daily_gallery.py --src "D:/Game/Saved/Screenshots" --out docs/gallery --title "第 12 周 · 每日巡览"

# 只看最近 7 天
python scripts/daily_gallery.py --src Saved/Screenshots --days 7 --out docs/gallery

# 对比改造前后两天（左 A、右 B）
python scripts/daily_gallery.py --src Saved/Screenshots --compare 2026-11-10,2026-11-14 --out docs/gallery

# 机器可读汇总（stdout 只有 JSON）
python scripts/daily_gallery.py --src Saved/Screenshots --json > docs/gallery/summary.json
```

### 参数

| 参数 | 默认值 | 作用 |
|---|---|---|
| `--src` | 无，必填 | 截图目录，递归扫描 |
| `--out` | 当前目录/gallery | 输出目录，写 index.html 与 index.md |
| `--title` | 每日截图巡览 | 页面标题，HTML 中会转义 |
| `--days N` | 不过滤 | 以最新截图的日期为基准，保留最近 N 个自然日 |
| `--compare A,B` | 无 | 生成两栏对比，左 A 右 B，缺一天会提示 |
| `--ext` | png,jpg,jpeg | 参与扫描的扩展名，逗号分隔、不区分大小写 |
| `--json` | 关 | stdout 只输出 JSON 汇总，不打印人类摘要 |

日期分组规则，按顺序执行：

1. 图片的**父目录名**是合法 `YYYY-MM-DD` → 用父目录日期；
2. 否则用文件 **mtime 的本地日期**；
3. 日期降序排列；同一天内按 mtime 升序；mtime 相同按文件名升序；
4. `--days` 在分组之后过滤，基准是**最新截图的日期**，不是运行脚本的今天。

### 退出码

| 退出码 | 含义 | 常见原因 |
|---|---|---|
| 0 | 成功 | 已生成 index.html、index.md |
| 1 | 无截图或参数错误 | 目录不存在、没有图片、`--days 0`、`--compare` 格式错、`--out` 等于 `--src` |
| 2 | 用法错误 | 参数拼错、缺 `--src`、`--help` 之外的错误调用 |

读退出码，不要读日志猜。

### 输出示例

以 `--out docs/gallery` 为例，只生成两个文件：

```text
docs/gallery/
├─ index.html      # 自包含样式，双击即可看；图片用相对路径
└─ index.md        # 日期 + 图片相对链接，便于贴进交付单/周报
```

`index.md` 片段【示例】：

```markdown
# 第 12 周 · 每日巡览

- 共 18 张截图 ｜ 3 天
- 生成时间：2026-11-14 21:05

## 2026-11-14（8 张）

- [P2_L02_001_overview.png](../../Saved/Screenshots/2026-11-14/P2_L02_001_overview.png) — 20:41:03 · 1.8 MB
- [P2_L02_003_jump.png](../../Saved/Screenshots/2026-11-14/P2_L02_003_jump.png) — 20:42:11 · 1.7 MB

## 2026-11-13（6 张）
```

`index.html` 提供：

- 顶部标题、总张数、总天数、生成时间；
- 每天一个区块，标题是日期与“共 N 张”；
- 每张图显示缩略图、文件名、完整时间、文件大小；点击原图在新标签打开；
- 移动端双列、桌面自适应多列；深色模式跟随系统；
- 样式全部内联，无外链 CSS、无 JS 依赖，断网可看。

### JSON 输出

`--json` 时 stdout 只有 JSON，适合接周报脚本：

```json
{
  "src": "D:\\Game\\Saved\\Screenshots",
  "out": "D:\\Game\\docs\\gallery",
  "days": 7,
  "total": 18,
  "dates": [
    {
      "date": "2026-11-14",
      "count": 8,
      "files": ["2026-11-14/P2_L02_001_overview.png"]
    },
    {
      "date": "2026-11-13",
      "count": 6,
      "files": ["2026-11-13/P2_L02_001_overview.png"]
    }
  ]
}
```

- `src`、`out` 是绝对路径；
- `days` 未指定时为 `null`；
- `total` 是过滤后实际展示的张数；
- `files` 是相对 `--src` 的路径，正斜杠。

## 用 --compare 看两天变化

```powershell
python scripts/daily_gallery.py --src Saved/Screenshots --compare 2026-11-10,2026-11-14 --out docs/gallery --title "L02 光照改造前后"
```

行为：

- 页面顶部生成两栏对比区，左栏是第一个日期，右栏是第二个日期；
- 每栏头部显示日期与张数，下面是与每日区块相同的图片卡片；
- 某一天没有截图时，该栏显示“该日期没有截图：YYYY-MM-DD”，命令仍返回 0；
- 对比区取**完整扫描结果**，不受 `--days` 过滤影响；每日区块仍按 `--days` 过滤；
- `index.md` 同步生成“对比”章节，方便贴进交付单。

对比有效的三个前提，缺一个结论无效：

| 前提 | 检查方法 | 不满足时 |
|---|---|---|
| 同机位、同 FOV | 两张图里门框/柱子在同一位置 | 重新摆机位再截，不用旧图凑 |
| 同分辨率、同后处理 | 文件属性都是 1920×1080；曝光/色调映射未改 | 把后处理参数写进变更单，同参数重截 |
| 只改一个变量 | 变更单里只有一项改动（光照/材质/模型） | 拆成两次对比，否则无法归因 |

常见用法【示例】：

- 白模 → 高模：`--compare 2026-10-20,2026-11-03`，看轮廓与比例是否保持；
- 光照改造：`--compare 2026-11-10,2026-11-14`，看主光方向、阴影硬度、色温；
- 性能优化：`--compare 2026-11-12,2026-11-13`，确认没有为了帧率删掉关键视觉锚点。

反例：左边用 1080p、右边用 4K，然后得出“右边更清楚所以更好”的结论——这不是对比，是两张不同条件的图。

## 每日流程（收工 15 分钟，其中巡览 5 分钟）

| 步骤 | 动作 | 耗时 | 产出 |
|---|---|---|---|
| 1 | 按当天 12 张配额截图，固定 1920×1080 | 8 min | `Saved/Screenshots` 里 1 天的图 |
| 2 | 让 agent 或自己跑生成命令 | 1 min | `docs/gallery/index.html`、`index.md` |
| 3 | 按 5 分钟计时翻 12 张图 | 5 min | 1 条具体问题（没有就写“无阻塞”） |
| 4 | 在交付单“证据”栏贴 2–3 张图的相对路径 | 1 min | 可追溯的交付记录 |
| 5 | 跑一次当天构建，确认下次能回滚 | 计入日常 | 可运行版本 + 当天 commit |

### 每日交付单里的证据写法【示例】

```markdown
| 项 | 证据 |
|---|---|
| L02 跳跃段 | docs/gallery/index.html（2026-11-14，图 P2_L02_003_jump.png） |
| 台阶问题 | 同上第 7 张；问题：台阶高 1.1 m，跳跃高 2.2 m，落点悬空 |
```

反例：只写“已完成，见截图”，不写目录、日期、文件名——周五无法复现，按未交付处理。

## 每周五流程（45–60 分钟）

与 `references/00-总览与协作.md` 的周五节奏对齐：截图巡览 + 交付单验收（D3）+ 下周目标。

| 步骤 | 动作 | 耗时 | 产出 |
|---|---|---|---|
| 1 | 生成一周巡览：`--days 7 --title "第 N 周"` | 1 min | 本周 7 天页面 |
| 2 | 周初 vs 周末：`--compare 周一,周五` | 2 min | 本周变化结论 |
| 3 | 翻 3 个关键关卡/系统，每处停 3 分钟 | 10 min | D3 验收或退回项 |
| 4 | 从巡览里挑 3 张进周报与交付单 | 10 min | 下周目标的可视依据 |
| 5 | 把本周精选图复制到 `docs/evidence/<日期>/` 并压缩 | 10 min | 入库证据 |
| 6 | 更新周报“证据”“阻塞”“下周计划” | 15 min | `docs/11_周报/<日期>.md` |

D3 验收结论只有两种：通过，或退回并列出退回项。写“感觉还行”不算验收。

## 提交策略：gallery/ 要不要入库

默认策略：**源截图与生成页都不入库，只把精选证据图入库。**

| 文件/目录 | 是否入库 | 理由 | 周期 |
|---|---|---|---|
| `Saved/Screenshots/` | 否 | 体积大、mtime 会被复制/解压改变、UE 目录本身有 Binaries 等产物 | 每次 |
| `docs/gallery/index.html`、`index.md` | 否（默认） | 生成物；图片用相对路径，源图不入库会破图 | 每次 |
| `docs/evidence/<日期>/*.png` | 是 | 交付单/周报引用的证据，必须可追溯 | 每周 ≤8 张 |
| `docs/evidence/<日期>/index.md` | 是 | 记录每张图对应的问题或验收项 | 每周 1 份 |
| 全量截图压缩包 | 否 | 备份到网盘/移动硬盘，不进 Git | 每周 1 次 |

`.gitignore` 追加【示例】：

```gitignore
# 每日截图巡览：源图与生成页不入库
Saved/Screenshots/
docs/gallery/
```

想让 `gallery/` 入库时，必须同时满足两条，否则页面必然破图：

1. 把被引用的图片复制进 `docs/evidence/`（不要引用 `Saved/`）；
2. 用 `--src docs/evidence --out docs/gallery` 重新生成，再一起提交图片与 index.html。

精选图标准【示例】：单张 ≤500 KB、每周 ≤8 张、总大小 ≤5 MB；超过就压分辨率到 1280 宽，保留原始 1920 图到网盘备份。截图里的 UI 文字不要压到看不清。

## 故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| 退出码 1，提示“没有找到图片” | 路径错、`--ext` 没包含实际格式、目录只有子目录无文件 | 用资源管理器确认图片存在；加 `--ext png,jpg,jpeg,webp`，但 webp 需浏览器支持 |
| 退出码 2 | 参数拼错、缺 `--src` | 跑 `--help` 对照；命令里路径含空格要加引号 |
| 日期分组全变成今天 | 图片被复制、解压、从手机传输，mtime 变成今天 | 改用日期父目录路线 B；或从原始 `Saved/Screenshots` 直接扫描 |
| 日期分组错误 | 父目录名不是 `YYYY-MM-DD`（如 `Windows`、`2026.11.14`） | 重命名目录，或让脚本回退到 mtime；不要混用两种路线 |
| 页面图片不显示 | 移动了 `--src` 或 `--out`，相对路径断裂 | 保持相对位置，重新生成；不要单独移动 index.html |
| `--compare` 提示缺一天 | 日期写错，或该天根本没有截图 | 看提示里的日期；只截了白模没截 UI 也算缺 |
| `--out 不能等于 --src` | 输出目录就是截图目录 | 换到 `docs/gallery` 或截图目录之外 |
| JSON 解析失败 | stdout 混入了其他输出 | 用 `--json` 时不要同时重定向 stderr；只解析 stdout |
| 中文标题/文件名乱码 | 终端不是 UTF-8 | 脚本已按 UTF-8 写文件；在 PowerShell 用 `chcp 65001` 后再看输出 |
