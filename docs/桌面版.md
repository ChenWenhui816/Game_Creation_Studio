# 桌面版构建与更新

> 目标：把 v0.4.0 的本地网页控制台打成 Windows 桌面应用。
> 前端与后端仍是同一套代码；桌面版只是多一个窗口壳与打包资源。

## 1. 产物

- Personal_Game_Studio_UE.exe：桌面窗口（pywebview / WebView2）；
- _internal/：Python 运行时与资源；
- 绿色版 zip：解压双击即可；
- 后续可加 Inno Setup 安装包。

## 2. 本地构建

```powershell
cd <repo>
python -m pip install -r requirements-desktop.txt
python -m PyInstaller --noconfirm --clean build/desktop.spec
# 输出 dist/Personal_Game_Studio_UE/
```

或直接：

```powershell
./build/build_desktop.ps1
```

## 3. 命令行

~~~powershell
Personal_Game_Studio_UE.exe                    # 最近项目 / 没有则新建向导
Personal_Game_Studio_UE.exe --project D:\games\my-game
Personal_Game_Studio_UE.exe --new              # 强制新建
Personal_Game_Studio_UE.exe --serve-only       # 只启动服务（调试）
Personal_Game_Studio_UE.exe --check-update     # 查 GitHub 最新版本
~~~

## 4. 桌面版启动流程

1. 读取 %LOCALAPPDATA%/Personal_Game_Studio_UE/settings.json 的最近项目；
2. 没有最近项目 → 新建项目向导；
3. 启动本地服务（随机空闲端口，只监听 127.0.0.1）；
4. 打开 pywebview 窗口；WebView2 缺失时退回系统浏览器；
5. 关闭窗口 → 停止服务；单实例互斥，避免开多个控制台。

## 5. 资源与项目数据

- App 内资源在 _MEIPASS：console_web/、templates/、scripts/、references/、docs/；
- 首次运行把 skill 释放到 %LOCALAPPDATA%/Personal_Game_Studio_UE/skill/<版本>/；
- 创建项目时复制 gamecheck.py + 模板 + store/ 到项目；
- 项目数据仍在用户选择的目录，不写安装目录。

## 6. 版本与更新

单一版本源：scripts/version.py 的 VERSION。

发布流程：

```powershell
# 1. 改 scripts/version.py、CHANGELOG.md
# 2. 提交并打 tag
git tag -a v0.4.0 -m "v0.4.0: 桌面版"
git push origin main
git push origin v0.4.0
# 3. GitHub Actions build-desktop 生成 zip artifact
# 4. 在 Releases 上传 zip / 安装包
```

桌面版内“检查更新”会调用 GitHub Releases API，只提示新版本与下载链接，不自动覆盖安装。
skill 资源随 App 版本发布；已有项目不会自动改文档，升级前先备份/提交。

## 7. 已知边界

- Windows 优先；macOS/Linux 需另测 WebView 依赖；
- 未做代码签名：首次运行可能触发 SmartScreen；
- WebView2 Runtime 通常随 Windows 10/11 提供；缺失时回退浏览器；
- 单文件 exe 不做（启动慢、杀毒误报）；使用 onedir + zip/安装包。
