# 代码签名指南 / Windows Code Signing

> 目标：让 Windows 安装包和 exe 显示可信发布者，减少 SmartScreen 警告。
> 现状：仓库已有签名链路；本地已用免费自签名证书签好 0.9.0，公共发布建议走 SignPath Foundation。

## 0. 不花钱的三种方案

| 方案 | 是否免费 | 信任范围 | 适合 |
|---|---|---|---|
| 自签名证书 | 是 | 只有导入该证书的电脑 | 你自己测试、内部机器 |
| SignPath Foundation | 是（符合 OSS 条件） | 公共 Windows 信任 | 公开开源项目 |
| Microsoft Store MSIX | 是（商店重签） | 公共 Windows 信任 | 通过 Microsoft Store 发布 |

注意：

- 真正公共可信 + 免费的常规路径是 SignPath Foundation（开源项目）或 Microsoft Store MSIX；
- 自签名不会让陌生用户的 SmartScreen 变信任，只能让导入证书的机器不报未知发布者；
- Azure Artifact Signing（原 Trusted Signing）约 $10/月起，不算免费；
- Certum 免费 OSS 证书已停止，当前 OSS 证书一般有项目门槛/付费。

build/certs/self-signed.pfx

证书主题：Game Creation Studio (Self-Signed)
证书已导入 当前用户 -> 受信任的根证书颁发机构。
已重新签 exe + setup；Get-AuthenticodeSignature 显示 Valid。

在新机器上使用：

~~~powershell
certutil -user -addstore Root build\certs\self-signed.cer
~~~

然后再安装/运行；没有导入证书的机器仍然不会信任。

### 0.2 SignPath Foundation（公共免费，推荐）

申请材料与仓库变量见 docs/SignPath免费签名申请.md。

条件（以官网为准）：

- OSI 认可的开源许可证（本仓库 MIT）；
- 项目活跃、已有 Release、文档完整；
- 无专有组件、无恶意软件；
- 证书签发给 SignPath Foundation，发布者显示 SignPath Foundation，不是个人名。

步骤：

1. 打开 https://signpath.org/apply 提交项目；
2. 审核通过后安装 SignPath GitHub App；
3. 在 SignPath 创建 project / signing policy / artifact configuration；
4. 在 GitHub Actions 加入 SignPath signing request；
5. 由 SignPath 签 exe 与 setup，替换未签名产物。

这条路不需要买证书，但需要项目审核，通常不是即时通过。

## 1. 先选证书类型

| 类型 | 价格量级 | 体验 | 适合 |
|---|---:|---|---|
| 自签名 | 0 | 别人电脑仍然警告/不信任 | 仅内部测试，不用于发布 |
| OV 代码签名 | 约 200-500 美元/年 | 需积累 SmartScreen 信誉 | 个人/小团队正式发布 |
| EV 代码签名 | 约 300-700 美元/年 | 通常更快建立信誉 | 商业发布、下载站 |
| 云签名（Azure Trusted Signing / DigiCert KeyLocker / SSL.com） | 按月/年 | 不用保管 PFX，合规更好 | 团队/CI |

2023 年后 OV/EV 通常要求硬件令牌或 HSM，不能只给一个 pfx 文件。
个人开发者先确认 CA 是否接受个人身份；部分 CA 只签企业。

推荐路径：

- 只想尽快减少警告：EV 证书或 Azure Trusted Signing（若符合资格）；
- 已经有企业：OV/EV + 硬件令牌；
- 只在 CI 签：云签名最省事。

## 2. 本仓库已有的签名链路

build/build_installer.ps1 会：

1. 先签 dist/Game_Creation_Studio/Game_Creation_Studio.exe；
2. 再用 Inno Setup 打包；
3. 最后签 Game_Creation_Studio-版本-setup.exe。

签名脚本：build/sign.ps1，支持三种凭据：

- SIGN_PFX_PATH + SIGN_PFX_PASSWORD：本地 PFX；
- SIGN_PFX_BASE64 + SIGN_PFX_PASSWORD：CI 用 base64 PFX；
- SIGN_CERT_SHA1 或 SIGN_CERT_SUBJECT：证书已装进 Windows 证书存储（硬件令牌/HSM）。

## 3. 用 PFX 本地签名

拿到 .pfx 后：

~~~powershell
$env:SIGN_PFX_PATH = "D:\certs\studio.pfx"
$env:SIGN_PFX_PASSWORD = "你的密码"

# 先构建 exe，再自动签 exe + setup
python -m PyInstaller --noconfirm --clean build/desktop.spec
powershell -ExecutionPolicy Bypass -File build\build_installer.ps1
~~~

只签一个文件：

~~~powershell
powershell -ExecutionPolicy Bypass -File build\sign.ps1 -Files "D:\path\app.exe" -Required
~~~

## 4. 用硬件令牌 / 证书存储签名

证书插在 USB Token 或 HSM，私钥不能导出：

~~~powershell
# 查看证书指纹
Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert |
  Select-Object Subject, Thumbprint, NotAfter

$env:SIGN_CERT_SHA1 = "证书指纹（去掉空格）"
powershell -ExecutionPolicy Bypass -File build\build_installer.ps1
~~~

签名时令牌可能弹出 PIN。用 /sha1 选择证书，不导出私钥。

## 5. GitHub Actions 签名

工作流已经读取：

- SIGN_PFX_BASE64
- SIGN_PFX_PASSWORD

在 GitHub 仓库 Settings -> Secrets and variables -> Actions 添加：

1. 本地生成 base64：

~~~powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("D:\certs\studio.pfx")) | Set-Clipboard
~~~

2. 粘贴为 SIGN_PFX_BASE64；
3. 密码设为 SIGN_PFX_PASSWORD；
4. push tag，workflow 自动签 exe 和 setup。

PFX 密码和 base64 都是敏感信息，不要提交到仓库。
更安全的方式是云签名/HSM，避免在 CI 传 PFX。

## 6. 验证签名

~~~powershell
Get-AuthenticodeSignature "D:\AI_Project\Deepseek\Creat_Game\Game_Creation_Studio\dist\Game_Creation_Studio-0.9.0-setup.exe" | Format-List Status, StatusMessage, SignerCertificate

& "C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\signtool.exe" verify /pa /v "D:\...\setup.exe"
~~~

期望：

- Status: Valid
- SignerCertificate.Subject 是你的公司/个人；
- 时间戳存在（证书过期后旧签名仍有效）。

## 7. SmartScreen 说明

- 自签名证书不会让陌生用户信任；
- OV 证书也需要下载信誉积累，早期仍可能提示；
- EV 证书通常更快建立信誉；
- 可以到 Microsoft Security Intelligence 提交文件误报/信誉：
  https://www.microsoft.com/en-us/wdsi/filesubmission
- 不要用破解版证书/共享证书，会吊销并影响发布。

## 8. 建议

1. 先决定：个人还是企业；
2. 选 EV（发布优先）或 Azure Trusted Signing（CI 优先）；
3. 拿到证书后设置上面的环境变量；
4. 重新构建 v0.9.0 安装包；
5. 用 signtool verify /pa /v 验证；
6. 在干净 Windows 机器上再测一次 SmartScreen。

当前仓库的 0.9.0 安装包仍是未签名；签名需要你提供证书，不能由代码生成可信证书。
