# 创作流程：想法 -> P0 -> P1 -> P3

> 目标：用户只提供想法、做破坏性重建和审核；agent 负责把想法展开成可判定文档。
> 原则：agent 不替用户冻结；用户不写正文，只砍/改方向/批准。

## 1. 角色分工

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 用户 | 一句话想法、范围上限、审美偏好；看 G0/G1/G3；做砍功能/推翻重建/冻结 | 不填模板、不写数值表、不做资产清单 |
| Producer agent | 把想法变成 P0 立项书、范围、风险、不做清单 | 不替用户批准范围 |
| Design agent | P1 GDD、关卡总表、核心循环、验收标准 | 不写引擎实现细节 |
| Tech agent | P1 技术方案、性能预算、工程目录、存档 | 不改玩法范围 |
| Art agent | P1 美术圣经、资产清单、风格锚点 | 不承诺未验证的 AI 资产 |
| DSH / 当前 agent | 按交接包推进、跑闸门、交证据 | 不跳过闸门、不冻结局 |

## 2. 一个循环

~~~text
用户：想法 + 上限（平台/时长/团队）
  -> agent：P0 立项书草案（1 页）
  -> 用户：只做三件事
       1) 砍掉不做清单里的东西
       2) 推翻一个不想要的方向
       3) 批准冻结
  -> 冻结 P0 -> 自动交接包
  -> agent：P1 GDD / 美术 / 技术 / 资产 / 数值草案
  -> 用户：审核 G1（可判定、无形容词、范围没膨胀）
  -> 冻结 P1 -> agent：P2 剧本/分镜，P3 白模/技术验证
~~~

## 3. 用户输入模板

~~~text
我想做：<一句话>
平台：Windows PC / 其他
体量上限：<小时/关卡数>
我最在意的三件事：<玩法/氛围/叙事/美术>
我绝对不要：<联机/开放世界/多结局...>
我能接受的资产来源：<自建/Blender/AI/商店>
~~~

## 4. agent 输出模板

每个阶段必须交：

- 版本化文档（docs/）；
- 跑闸门的命令与退出码；
- 证据（截图/录屏/日志/测试记录）；
- 待决策 <=3 条；
- 不做的清单。

## 5. 冻结与推翻

- 用户说「冻结」才冻结；
- 冻结后改内容走变更单；
- 用户说「推翻重来」时，agent 从 P0 重新发散，不修补旧稿；
- 每次推翻保留旧版快照，不删除。

## 6. DSH 按钮

冻结弹窗里的「让 DSH 继续」= 用户批准下一步；agent 用当前 DSH 会话读交接包。
没有 DSH 时用「复制给 Agent」。

## 7. 质量标准

- 每条能判定：数字带单位、否定用「禁止」、验收有方法；
- 文档阶段 0 个待填标记；
- 闸门全绿才允许冻结；
- 用户只审核方向，不审格式。

---

### English Summary

The user gives one idea, a scope cap and taste boundaries; agents expand it into P0, then P1, then P2/P3. The user only removes things, rebuilds direction, and approves freezes. Agents never freeze on their own.
