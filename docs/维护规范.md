# 维护规范：章节约定与写作标准

> 给维护者与贡献者。改模板、references、校验器之前先读本文件。
> 核心约束：**模板的 H2 章节名、校验器的 REQUIRED_SECTIONS、测试断言三处必须一字不差**，否则 CI 会红。

## 1. 目标读者与语气

- 第一读者：**接活儿的 AI agent**。它读完后必须能直接执行，不需要再问“具体怎么做”。
- 第二读者：**项目负责人（一个人，非程序出身，每周只有 3–4 小时）**。他只用它做 D1/D2/D3 三类决策。
- 简体中文；动词开头；祈使句；不写营销话术，不写“你可以考虑”。
- 每条建议尽量带**数字、阈值、示例、反例**。禁止“尽量”“适当”“差不多”“好看”“流畅”这类不可判定的词（除非作为反例出现）。
- 表格优先于段落。单个表格不超过 12 行，超了就拆。

## 2. 统一术语（不得自造）

| 术语 | 含义 |
|---|---|
| 阶段 P0–P5 | 立项 / 标准 / 白模 / 资产管线与垂直切片 / 内容生产 / 打磨与 Demo 上线 |
| 闸门 G0–G5 | 每个阶段结束的通过标准，必须可判定 |
| D1 需求决策 | 做什么、砍什么；产出立项书或变更单 |
| D2 素材决策 | 从 A/B/C 三版选一版；产出验收单 |
| D3 验收决策 | 资产/系统能否进游戏；产出验收单 |
| 交付单 | agent 每次任务的汇报格式（目标/改动/证据/已知问题/待决策） |
| 验收单 | 对单个资产或系统的逐项判定 |
| 变更单 | 任何改范围、改数值、改风格、影响 >1 天工作量的改动 |
| 标准书 | GDD + 美术圣经 + 技术方案 + 验收标准的总称，唯一真相源 |
| 白模 / 灰盒 | 无最终美术的可玩关卡，只验证空间、手感、节奏 |
| 垂直切片 | 1 个完整关卡 + 核心系统 + 成品美术，证明管线可复现 |
| 资产工厂 | 从导出文件到 UE 资产的确定性导入流程 |

## 5. 每份 references 文档的统一结构

1. 一级标题（阶段名）
2. 一行引用块：`> 适用阶段：P? ｜ 何时加载：…… ｜ 上游：…… ｜ 下游：……`
3. `## 这一阶段要回答的问题`（3–6 个问句）
4. `## 输入`（开工前必须存在的东西）
5. `## 步骤`（编号，可执行；每步写清谁做、做什么、产出什么）
6. `## 产出`（文件清单 + 每份文件的一句话用途）
7. `## 闸门 G?`（判定项、命令、不合格怎么办）
8. `## 反模式`（表格：表现 / 后果 / 对策）
9. `## 检查清单`（勾选项，10–15 条）

## 6. 质量红线

- 不编造 UE/Steam/Epic 的 API、价格、政策；不确定的参数标“以官方文档为准”并给官方链接。
- 不写“AI 一键生成完整游戏”这类承诺；明确 AI 的边界（拓扑、UV、一致性、玩法判断）。
- 数值示例必须自洽：跳跃高度 h、到顶点时间 t、重力 g=2h/t²、起跳速度 v=2h/t；水平距离 = 跑速 × 2t，不能用垂直起跳速度算水平距离。
- 每份文档至少给出 1 个正例、1 个反例。
- 占位符统一写 `【待填】`，示例值统一标 `【示例】`。
- 模板必须能直接复制使用：留空处给一行填写说明，不写大段教程。
- 不要为凑字数灌水；references 250–450 行，模板 40–160 行。

## 7. 交叉引用规则

- 引用 skill 仓库内文件用相对路径，例如 `references/03-美术资产管线.md`、`templates/08_验收单.md`。
- 引用项目内文件用项目相对路径，例如 `docs/05_资产清单.csv`。
- 提到阶段/闸门必须带编号：P2、G2，不写“中期阶段”。
- 项目内命令统一写 `python scripts/gamecheck.py <子命令> --root .`（init 已把校验器复制进项目）。

## 8. 改动联动清单（缺一项 CI 或体验就会坏）

| 改动 | 必须同步 |
|---|---|
| 改模板 H2 章节名 | `scripts/gamecheck.py` 的 `REQUIRED_SECTIONS`、`tests/test_gamecheck.py`、本文件 §4 |
| 新增模板 | `gamecheck.py` 的 `TEMPLATE_FILES`/`TEMPLATE_DEST`、`init` 测试、README 目录、CHANGELOG |
| 新增校验规则 | 新命令的 `--help`、`--show-rules`、至少 1 个正例与 1 个反例测试、references 中说明 |
| 改数值 key | `templates/06_数值表.csv`、`NUM_KEY_ALIASES`、`references/02` 示例、`templates/01` 引用 |
| 改阶段/闸门定义 | `SKILL.md` 路由、`references/00`、README、`docs/设计说明.md` |
| 改资产清单/变更单字段 | `templates/05`、`templates/09`、`gamecheck.py` 的 `check_changes`、`change check` 测试、`references/02` |
| 改商店素材命名/尺寸 | `templates/13`、`gamecheck.py` 的 `STORE_CAPSULES`、`check_store_assets`、发布测试、`references/05` |
| 发布新版本 | `CHANGELOG.md`、Git tag、GitHub Release（见 `docs/GitHub发布指南.md`） |

## 9. 本地测试

```powershell
python -m unittest discover -s tests -v
python scripts/gamecheck.py --help
python scripts/gamecheck.py --show-rules
```

测试临时目录在 `tests/_tmp/`（已 gitignore）；CI 在 Windows 与 Ubuntu 双平台跑同一套测试。
