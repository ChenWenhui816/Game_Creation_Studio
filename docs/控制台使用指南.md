# 制作控制台使用指南（v0.7.5）

> 这是 skill 的可视化操作层：把 P0–P7 八条管线、闸门、交付单、版本与冻结变成本地网页。
> 项目文件仍然全部在本地；控制台只维护状态、版本副本与快照。
> 启动前先读 `SKILL.md` 的阶段规则；控制台不改变“标准书是唯一真相”的原则。

## 1. 它解决什么

- 不用记一堆命令，打开网页就能看到当前阶段、缺什么、闸门过没过。
- 每个环节（P0–P7）有独立的本地文件夹与版本副本，方便直接打开资源管理器阅读。
- agent 的交付单、证据、状态进入“交接收件箱”，你点通过/退回。
- 保存 / 冻结 / 下一步有明确状态；冻结后文档锁定，必须走变更单。

## 2. 启动

### 2.1 新建项目（推荐首次使用）

```powershell
cd <skill 目录>
python scripts/gameconsole.py serve
```

浏览器打开启动日志里的地址（默认 <http://127.0.0.1:8765/>），按向导：

1. 填项目名 + 游戏想法（一句话或三句话）；
2. 选择工程创建路径（可在网页里浏览目录）；
3. 点“创建本地工程”。

控制台会调用 `gamecheck.py init` 创建项目骨架，然后写入 P0 立项书草稿、`.gameconsole/` 状态、`stages/` 八个环节文件夹，并自动进入 P0 面板。

### 2.2 打开已有项目

```powershell
python scripts/gameconsole.py serve --project D:\games\my-game
```

如果项目是旧版（只有 `docs/`，没有 `.gameconsole/`）：

```powershell
python scripts/gameconsole.py adopt --project D:\games\my-game
```

`adopt` 只创建控制台状态与阶段文件夹，不改 `docs/` 内容。

### 2.3 无界面命令

```powershell
python scripts/gameconsole.py init --project D:\games\my-game --name "生命之泉" --idea "一句话想法"
python scripts/gameconsole.py status --project D:\games\my-game --json
python scripts/gameconsole.py gate --project D:\games\my-game --stage P0
python scripts/gameconsole.py freeze --project D:\games\my-game --stage P0
python scripts/gameconsole.py next --project D:\games\my-game --stage P0
python scripts/gameconsole.py submit --project D:\games\my-game --stage P0 --title "立项初稿" --note "附证据"
```

## 3. 网页怎么用

### 3.1 阶段地图

左侧是 P0–P7；圆点颜色：

| 颜色 | 状态 | 含义 |
|---|---|---|
| 蓝 | drafting | 草稿，可编辑 |
| 黄 | review | agent 已提交，等你验收 |
| 绿 | frozen | 已冻结，文档锁定 |
| 红 | blocked | 被闸门/依赖卡住 |

顶部显示项目名、当前阶段、收件箱入口。

### 3.2 环节工作台

- 左侧文档树：点文档打开；
- 中间 Markdown 编辑 + 实时预览；
- 右侧闸门结果、版本列表、本地阶段目录。

### 3.3 保存 / 冻结 / 下一步

| 按钮 | 行为 | 限制 |
|---|---|---|
| 保存 | 写回 `docs/`，每次保存生成版本副本 | 冻结文档不可保存 |
| 运行闸门 | 调用 `gamecheck.py` 对应阶段命令 | 只读判定，不改文档 |
| 冻结 | 先跑闸门；通过后复制阶段文档到快照并锁定 | 只有当前阶段可冻结；闸门失败不可冻结 |
| 下一步 | 打开下一阶段 | 当前阶段必须 frozen |
| 恢复版本 | 把历史版本写回当前文档 | 会先保存当前内容为新版本 |

冻结后：

- `docs/` 文件仍可本地打开，但通过控制台保存会被拒绝（423）；
- 想改必须先开变更单；批准后进入“变更中”，修改完重新冻结；
- 旧快照永久保留在 `stages/<环节>/frozen/<时间>/`。

### 3.4 变更单

冻结后文档锁定；顶部「变更单」可以：

1. 选择阶段、填标题/原因/影响文档；
2. 创建变更单（pending）；
3. 批准后阶段进入「变更中」，文档解锁；
4. 修改后重新冻结；变更单自动标记 applied。

拒绝则保持原冻结状态。

### 3.5 章节 / 检查项层级

阶段右侧「章节」面板解析当前 Markdown 的 H2/H3 与 checkbox：

- 点标题跳到对应行；
- 点检查项切换 [ ] / [x]；
- 「+ 章节」「+ 检查项」追加到文档末尾；
- 修改后仍需点「保存」，会生成版本。

### 3.6 冻结交接

冻结后自动生成 `.gameconsole/handoff/` 交接包：

- 页面弹窗可复制给当前 agent；
- P0→P1 自动把 P0 事实播种到 G1 文档；
- 如果配置 `.gameconsole/agent.json`，桌面版会自动启动 agent_bridge 派发。

详见 docs/交接与Agent桥.md。

### 3.7 预览直接编辑与填写区

- 预览可直接点击段落、表格单元格、列表、引用修改；
- 失焦后自动写回 Markdown，点保存生成版本；
- 标题、代码块、冻结文档保持只读。

### 3.8 填写区与高亮

- 预览中黄色 = 【待填】，灰色/左侧线 = 固定章节；
- 编辑器上方「填写区」列出所有待填字段，填入后自动替换；
- 冻结文档显示“全文只读”。

### 3.9 证据墙

顶部「证据墙」读取项目的 docs/evidence/：

- 图片/视频内嵌预览；
- 其他文件显示为文件卡片；
- 点开可新窗口查看原文件。

agent 把截图/录屏放进 docs/evidence/ 后，刷新即可看到。

### 3.7 diff / 证据上传 / 章节拖拽

- 修改高亮：阶段右侧显示相对最近冻结快照或初始版本的变更文档、增删行；点文档查看统一 diff。
- 影响推理：根据修改内容中的关键词，提示 P2/P3/P5 下游需要同步的文档。
- 证据上传：证据墙里拖拽或选择文件，上传到 docs/evidence/，单文件 ≤ 6 MB。
- 章节拖拽：章节面板的 H2 章节左侧有拖拽手柄，拖动后保存即可重排。
- 总览：右上角「总览」查看阶段完成环、闸门/文档统计、阶段时间柱状图与最近计时。
- 计时：右上角「开始计时 / 停止计时」按当前阶段记录真实制作时间。

## 4. 本地文件夹结构

```text
<项目>/
├─ docs/                       # 文档本体（唯一真相源）
├─ stages/                     # 每个环节一个可读文件夹
│  ├─ 00_立项/
│  │  ├─ README.md             # 本阶段状态/文档链接/闸门
│  │  ├─ versions/             # 每次保存的版本副本
│  │  └─ frozen/               # 冻结快照（含 freeze.json）
│  ├─ 01_标准/
│  ├─ 02_剧本/
│  ├─ 03_白模与技术/
│  ├─ 04_美术与视频/
│  ├─ 05_音乐与音频/
│  ├─ 06_内容生产/
│  └─ 07_上线与发行/
├─ .gameconsole/
│  ├─ state.json               # 阶段/闸门/当前阶段/交付单
│  ├─ audit.jsonl              # 追加审计
│  ├─ versions/index.json      # 全项目版本索引
│  ├─ outbox/                  # agent 提交
│  └─ inbox/                   # 你给 agent 的请求（v0.3.1 使用）
├─ game/                       # UE 工程
├─ art/  assets/  store/
├─ gamecheck.json
└─ AGENTS.md
```

版本副本命名：`<时间戳>__<原文件名>`，可直接在资源管理器里双击打开。
建议把 `.gameconsole/versions/`、`stages/*/versions/`、`stages/*/frozen/` 排除出 Git（如果项目用 Git），文档本体照常提交。

## 5. agent 如何交接

agent 不操作浏览器，用 CLI 写状态：

```powershell
python <skill>/scripts/gameconsole.py submit --project . --stage P0 --title "立项初稿" --note "已补三句话与不做清单" --evidence docs/evidence/p0.png
```

网页“收件箱”会出现这张交付单；你点“通过”后阶段进入 review，“退回”可写原因。
agent 要继续干活时，先读：

```powershell
python <skill>/scripts/gameconsole.py status --project . --json
```

## 6. 安全与边界

- 只监听 `127.0.0.1`，不对外网开放；
- 控制台只允许修改 `docs/` 下的文件，拒绝 `..` 路径穿越；
- 状态文件与版本目录都在项目内，可随时备份/删除（删除后需重新 `adopt`）；
- 不替代 `gamecheck.py`：所有闸门仍由 gamecheck 判定；
- 当前为单人本地版；多用户/云端同步不在范围内。

## 7. 常见问题

| 问题 | 处理 |
|---|---|
| 端口 8765 被占用 | 控制台会自动 +1 尝试；或 `--port 8876` |
| 浏览器打不开 | 手动打开日志里的地址；确认只在本机 |
| 页面提示“尚未创建项目” | 走新建向导，或 `serve --project <路径>` |
| 保存被拒绝（423） | 该文档所属阶段已冻结；开变更单后解冻 |
| 外部改了文件后保存冲突（409） | 刷新页面重新打开文档，再保存 |
| 想回到旧版本 | 右侧版本列表点“恢复”；旧版本在 `stages/<环节>/versions/` |
| 项目移动了目录 | 用新路径 `serve --project`；`.gameconsole/state.json` 中的路径可手动改 |
| 页面样式坏了 | 强制刷新；确认 `console_web/` 与脚本同属 skill 目录 |

## 8. 与 skill 的关系

- `SKILL.md` 仍是规则入口；控制台只是把规则变成按钮。
- `gamecheck.py` 仍是唯一闸门判定器；控制台不复制检查逻辑。
- `docs/` 仍是唯一真相源；`stages/` 是阅读与版本副本。
- 升级 skill 后重启控制台；已有项目状态兼容（schema 1）。
