# 安装包与代码签名

## 1. 安装包

构建：

```powershell
# 先构建桌面版
python -m PyInstaller --noconfirm --clean build/desktop.spec
# 再构建安装包
.\build\build_installer.ps1
```

输出：

```text
dist/Personal_Game_Studio_UE-<版本>-setup.exe
```

安装器行为（build/installer.iss）：

- 默认安装到 %LOCALAPPDATA%\Programs\Personal_Game_Studio_UE，不需要管理员权限；
- 开始菜单快捷方式；
- 卸载入口；
- 可选桌面快捷方式；
- 安装后启动；
- 卸载时清理安装目录下的 appdata。

## 2. 代码签名：先说结论

代码签名不能只靠“生成一个证书”解决 SmartScreen。必须使用受信任的代码签名证书：

| 方案 | 是否能减少 SmartScreen | 成本 | 说明 |
|---|---|---|---|
| 自签名证书 | 否 | 0 | 只有本机受信任，其他机器仍警告 |
| OV 代码签名证书 | 需要积累信誉 | 约 $100–$300/年 | 新证书仍可能先警告，需下载量积累 |
| EV 代码签名证书 | 通常立即受信任 | 约 $300–$600/年 | 硬件令牌/云 HSM，审核更严 |
| Azure Trusted Signing | 推荐 | 按签名次数/订阅 | 微软云签名，适合 CI，需资质审核 |

没有证书时，安装包仍可用，但 Windows 会显示“未知发布者”。本项目已把签名步骤做成可选：没有证书就跳过，不阻塞构建。

## 3. 本地签名

准备 .pfx：

```powershell
$env:SIGN_PFX_PATH = "D:\certs\my.pfx"
$env:SIGN_PFX_PASSWORD = "your-password"
.\build\sign.ps1 -Files .\dist\Personal_Game_Studio_UE\Personal_Game_Studio_UE.exe -Required
```

或在构建安装包时自动签 exe + setup：

```powershell
.\build\build_installer.ps1
```

## 4. GitHub Actions 签名

在仓库 Secrets 中配置：

- SIGN_PFX_BASE64：pfx 文件 base64；
- SIGN_PFX_PASSWORD：pfx 密码。

build-desktop workflow 会自动：

1. 构建 exe；
2. 有 Secrets 就签名 exe；
3. 构建安装包；
4. 签名 setup；
5. 上传 zip + setup 到 Release。

不要把 pfx 提交到仓库；只放 Secrets。
时间戳服务使用 DigiCert；如企业要求可换。

## 5. SmartScreen 现实预期

- 首次发布的新证书仍可能被 SmartScreen 警告；
- EV 证书或 Azure Trusted Signing 体验最好；
- 签名后仍需用户下载/安装量积累信誉；
- 代码签名不能替代杀毒软件扫描；发布前建议 VirusTotal 自检。

## 6. 没有证书时

当前构建产物是未签名的，首次运行可能出现“Windows 已保护你的电脑”。用户可点“更多信息 → 仍要运行”。正式分发前建议购买证书或使用 Azure Trusted Signing。
