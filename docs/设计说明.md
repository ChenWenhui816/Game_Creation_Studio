# 设计说明：从你的一页设想，到一套可执行流程

> 本文说明这套 skill 是如何从 `游戏开发skill.docx` 长出来的：哪些内容保留、哪些被改写、为什么改。
> 读完后你应该能判断：这套流程是否符合你的项目，以及下一步先做什么。

## 1. 原文档在说什么

原文档标题：**《基于 UE5 的单角色单机闯关三维游戏 Skill》**，正文约 700 字，分五个部分：

| 原文部分 | 核心内容 |
|---|---|
| 1. 项目立项（头脑风暴） | 一段"世界背景 + 角色 + 突发事件 + 目标 + 成长 + 结局"的填空公式；随后列了 12 个待推敲项：核心动作、核心循环、核心爽点、闭环逻辑、游戏特色、单局时长、世界背景、主线支线、素材需求、避免雷区、自我校验 |
| 2. 前期筹备（概念、美术、技术文档制作） | 美术线（图像生成 agent + 需求者）；9 个设计项：角色、场景、道具、气氛、角色动效、场景特效、UI、PV、图标；游戏开发文档；"每一项提交审核，确认后进行下一项" |
| 3. 中期筹备 | 一句话流水线：风格锁定 → 资产生产 → 入库 → 集成 |
| 4. 中期引擎制作实现 | 技术线（agent 的 MCP 服务 + 需求者）；素材导入内容浏览器；按开发文档新建关卡，遇到问题先问需求方；流水线：技术底座 → 白模 → 系统 → 测试 → 高模替换 → 玩法实现 → 光影氛围 → 关卡 → 打包 |
| 5. 游戏 Demo 上线指导 | 检索游戏社区指引；Epic、Steam 等平台 Demo 上线 |

这份文档的价值在于**骨架是对的**：它已经意识到"需求 → 标准 → 资产 → 引擎 → 上线"的主干，也抓住了"AI 生成 + agent 开发 + 人做决策"的分工。问题不在方向，在**颗粒度和可执行性**。

## 2. 原文档的八个不足

| # | 不足 | 具体表现 | 后果 |
|---|---|---|---|
| 1 | 只有环节名，没有判定标准 | "前期筹备完成"没有定义；"审核通过"没有检查项 | 每个阶段都能自称完成，问题滚到下一阶段 |
| 2 | 流程是串行的，没有验证点 | 立项 → 文档 → 资产 → 引擎，一路向前 | 一旦方向错，发现时已经烧掉一半预算 |
| 3 | 资产量产早于玩法验证 | 中期筹备先"资产生产"，引擎阶段才"白模" | 玩法不好玩时，已生产的资产全部贬值 |
| 4 | 没有分工与决策边界 | 只说"需求者 + agent"，没说谁决定什么 | 你要么被琐事淹没，要么 agent 自行其是 |
| 5 | 没有成本/产能核算 | 没算过"多少资产 × 多少工时 ÷ 每周几小时" | 排期必然乐观，做到一半发现做不完 |
| 6 | 没有证据与验收机制 | 没有交付物格式、没有截图/录屏要求 | 无法判断 agent 是否真的做完 |
| 7 | 没有变更与版本管理 | 没提标准冻结、变更单、数值唯一来源 | 半年后没人知道哪份文档是对的 |
| 8 | 上线太晚 | Demo 上线放在最后一步 | 商店页、愿望单、审核都需要提前量 |
| 9 | 3D 管线缺失 | 只有"图像生成"，没有 AI 图生 3D、重拓扑、UV、绑定、UE 导入的具体做法 | 资产"看起来有"，但进不了引擎 |
| 10 | "自我校验"没有方法 | 只列了词，没有校验问题清单 | 立项质量靠感觉 |

另外有几处细节：原文第 3 部分"中期筹备"没有编号；"单局时常"应为"时长"；"agent 的 MCP 服务急"应为"接入"；"每一项提交审核"在一个人每周 3 小时的情况下不可持续。这些都在新流程里修掉了。

## 3. 改造后的骨架

把原来的"串行五段"改成"六个阶段 + 六道闸门 + 三类决策"：

| 原文档 | 新流程 | 产出 | 闸门 |
|---|---|---|---|
| 1 项目立项 | **P0 立项**（第 1 周） | `docs/00_立项书.md` | G0 陌生人能复述 |
| 2 前期筹备 | **P1 标准与文档**（第 2–3 周） | GDD / 美术圣经 / 技术方案 / 关卡总表 / 资产清单 / 数值表 | G1 每条标准可判定 |
| （原文缺） | **P2 技术底座 + 白模**（第 3–6 周） | 可运行工程 + 灰盒关卡 + 手感参数 | G2 盲测通过 |
| 3 中期筹备 | **P3 风格锁定 + 资产管线 + 垂直切片**（第 6–12 周） | 资产工厂 + 1 关完整流程 | G3 新资产 30 分钟入库 |
| 4 中期引擎实现 | **P4 内容生产**（第 13–22 周） | 全部关卡/敌人/剧情 | G4 全流程通关 |
| （原文缺） | **P5 打磨 + Demo 上线**（第 23–28 周） | 性能/本地化/商店页/Demo | G5 上线清单 |
| 5 Demo 上线 | 并入 P5 | `docs/12_Demo上线清单.md` | 同 G5 |

关键改动：**把"白模验证"从引擎阶段里提出来，单独成 P2**。原文把白模放在"中期引擎实现"的第 2 步，但那一步之前已经做了全部资产——顺序反了。玩法不成立时，最贵的资产已经做完了。

## 4. 逐条对照：保留了什么、改了什么

### 4.1 项目立项（头脑风暴）

**保留**：核心公式、12 个推敲项、"自我校验"的意识。

**升级**：

- 公式保留原文，但补了 2 个完整填写示例（科幻 / 奇幻各一），并说明"每一格必须能用一句话回答，答不上就是没想清楚"。
- 12 个推敲项每一项都配了"判定问题 + 合格示例"，从"待填"变成"能判"。
- 新增 3 轮提问脚本：世界/角色/冲突 → 动词/循环/爽点 → 规模/平台/不做。agent 可以直接照着访谈。
- 新增三个对标表（玩法 / 美术 / 体量），要求写"学什么、不学什么、差多少"。
- 新增规模表与两笔核算：内容时长 = 关卡 × 单关分钟；美术工时 = 资产件数 × 单件工时 × 1.3。
- 新增 Top5 风险登记与 G0 判据（陌生人复述 + 闭环无断点 + 规模自洽 + 不做清单 ≥5 条）。
- 对应文件：`references/01-立项.md`、`templates/00_立项书.md`。

### 4.2 前期筹备（概念、美术、技术文档制作）

**保留**：9 个设计项（角色 / 场景 / 道具 / 气氛 / 动效 / 特效 / UI / PV / 图标）和"先出文档再动手"的顺序。

**升级**：

- 把"一堆设计项"重组为**四本标准书**：游戏设计文档（GDD）、美术圣经、技术方案、验收标准；再加三份计划：关卡总表、资产清单、数值表。
- 9 个设计项分别落到 GDD（玩法/故事）、美术圣经（视觉/动画/UI/VFX）、资产清单（每个资产一行），不再散落。
- 把"每一项提交审核，确认后进行下一项"改成**批次评审 + 抽检**：前 20 个资产逐张签，之后每批抽检 20%。按你每周 3 小时算，逐项审核是排不下的。
- 新增"可判定"写作法：每条标准必须机器可查或人眼 3 秒可判，附 12 组正反例。
- 新增数值推导：先定三把尺（角色 1.8m、跳跃 2.2m、到顶点 0.4s），反推重力 27.5 m/s²、起跳速度 11 m/s。数值只写进 `06_数值表.csv`。
- 对应文件：`references/02-文档与标准.md`、`templates/01`–`06`。

### 4.3 中期筹备（风格锁定 → 资产生产 → 入库 → 集成）

**保留**：四个环节及其顺序；"AI 生成 + 人做风格决策"的分工。

**升级**：

- 从 4 个词扩成 9 步管线：概念图 → 风格锚点/LoRA → 白模 → AI 图生 3D → Blender 重拓扑/UV → PBR 贴图 → 绑定动画 → UE 导入 → 登记集成。
- 明确 AI 图生 3D 的边界：网格只能当参考，必须重拓扑、重展 UV、校正比例，否则不能进游戏。
- 新增资产预算表（面数 / 贴图 / 材质槽 / LOD / 碰撞）与验收单。
- 新增一致性控制：15–30 张风格锚点、提示词宪法、每批首张必审、漂移信号（第 20–30 张开始偏）。
- 新增授权记录：模型 / 版本 / prompt / seed / 来源 / 许可，写进资产清单。
- **顺序修正**：这一段整体后移到 P3，在白模验证之后；P1 只做概念设计，不做量产。
- 对应文件：`references/03-美术资产管线.md`、`templates/02_美术圣经.md`、`05_资产清单.csv`、`08_验收单.md`。

### 4.4 中期引擎实现

**保留**：整条流水线"技术底座 → 白模 → 系统 → 测试 → 高模替换 → 玩法实现 → 光影氛围 → 关卡 → 打包"，以及"遇到问题先问需求方"的原则。

**升级**：

- 把一条线拆成三轮迭代：
  - P2：工程配置 + 角色控制器 + 白模 + 盲测；
  - P3：系统骨架 + 1 关垂直切片 + 高模替换；
  - P4：批量内容 + 性能与稳定性。
- 明确"测试 → 高模替换 → 玩法实现 → 光影"的顺序不能乱：先玩法成立，再换皮，最后打光。
- 新增工程配置清单（UE 5.8+、插件、Lumen/Nanite、单位 cm、固定 60fps）、目录与命名规范。
- 新增角色参数表（跳跃 2.2m / 到顶点 0.4s / 重力 27.5 / 起跳 1100 cm/s / 跑速 6m/s / coyote 0.1s / buffer 0.1s）。
- 新增 MCP 操作规范与禁区：本机、串行、feature 分支、每日 commit、禁止直改 main / 删源资产 / 升引擎。
- 新增测试与性能预算、打包命令、Git LFS 与分支策略。
- 对应文件：`references/04-引擎实现.md`、`templates/03_技术方案.md`、`06_数值表.csv`、`07_交付单.md`、`10_测试记录.md`。

### 4.5 游戏 Demo 上线指导

**保留**：检索社区指引、Epic/Steam Demo 上线。

**升级**：

- 从"上线"扩展成 P5 打磨 + 上线：手感 → 反馈 → 引导 → 难度 → 可访问性 → 本地化 → 性能 → 商店。
- 加入具体提前量：Steam 商店页提前 6 个月；垂直切片后发 Demo；上线前 8 周内容冻结。
- 加入平台流程：Steam（$100 账号费、Demo/Playtest、Next Fest、审核、成就/云存档/手柄/Steam Deck）、Epic（自发行申请、12% 分成）、itch.io 早期 Demo。
- 新增 `docs/12_Demo上线清单.md`（6 类、40+ 项复选框），`gate release` 会检查未勾选项。
- 对应文件：`references/05-打磨与Demo上线.md`、`templates/12_Demo上线清单.md`。

## 5. 保留的四个核心判断

你的原始设想里有四件事是对的，新流程完整保留：

1. **AI 生成 + agent 开发 + 人做决策** 的三角分工。人负责审美、取舍、验收；agent 负责执行与记录。
2. **风格锁定 → 资产生产 → 入库 → 集成** 的顺序。这是资产不漂移的前提。
3. **技术底座 → 白模 → 系统 → 测试 → 高模替换 → 玩法 → 光影 → 关卡 → 打包** 的工程流水线。新流程只是把它拆成可验证的轮次。
4. **Demo 上线**是项目的终点，不是"做完再说"的附赠项。

## 6. 新增的五个机制

| 机制 | 解决什么 | 落在哪 |
|---|---|---|
| 闸门 G0–G5 | 每阶段有明确出口，不靠感觉 | `scripts/gamecheck.py` + SKILL.md |
| 三类决策 D1/D2/D3 | 你只做该做的决策，其余下放 | `references/00` |
| 交付单 / 验收单 | 每次交付有证据，资产有逐项判定 | `templates/07`、`08` |
| 变更单 + 数值单一来源 | 改需求可追踪，数值不打架 | `templates/09`、`06` |
| 风险与砍功能协议 | 范围失控时知道先砍什么 | `references/06` |

## 7. 关键数字从哪来

| 数字 | 依据 |
|---|---|
| 重力 g = 2h/t²；起跳速度 v = 2h/t | 匀加速运动公式；h=2.2m、t=0.4s → g=27.5 m/s²、v=11 m/s |
| 水平跳跃距离 = 跑速 × 2t | 6 × 0.8 = 4.8 m；空档取 3.5–4.2 m（留 12%–27% 容错） |
| UE 单位 1 uu = 1 cm | UE 默认；角色 1.8m = 180 uu |
| 角色面数 3–8 万、敌人 1–3 万、场景模块 1k–5k | 风格化 3D 的常见预算；Nanite 可放宽但骨骼网格不支持 |
| Steam Direct $100 / 款 | Steamworks 官方；以官方最新说明为准 |
| Epic 分成 12% | Epic Games Store 官方政策；以官方最新说明为准 |
| 28 周（保守排期）/ 每周你 3–4 小时 | 按"小品级"估算；agent 每周 24 h 时约 16–20 周；含 30% 返工留白 |

> 平台费用与分成会变，签约前以官方页面为准。

## 8. 需要你拍板的五个决策

| # | 决策 | 建议 | 影响 |
|---|---|---|---|
| 1 | 规模 | 首作按"小品"：3 关、5 敌人、1 Boss、12–16 周生产 + 上线缓冲 | 决定后面所有产能计算 |
| 2 | 引擎版本 | UE 5.8+，项目期内固定，不升级 | 升级会破坏插件/MCP/资产兼容 |
| 3 | 首发平台 | Windows + Steam 优先；Epic/itch 作为补充 | 决定打包、认证、商店素材 |
| 4 | 美术来源 | AI 生成 + 人工修整 + 重拓扑；关键角色人工重绘 | 决定资产管线与预算 |
| 5 | 时间预算 | 每周 3–4 小时，28 周；低于 2 小时/周建议缩到 1 关 | 决定排期是否现实 |

这五个决策写进 `docs/00_立项书.md` 后就冻结；之后要改，走变更单。

## 9. 怎么用这套东西

```bash
# 1. 生成项目骨架
python Personal_Game_Studio_UE/scripts/gamecheck.py init --dir D:\games\my-game --name "我的游戏"

# 2. 从 P0 开始：填 docs/00_立项书.md，过 G0
python Personal_Game_Studio_UE/scripts/gamecheck.py doc check --stage 0 --root D:\games\my-game

# 3. 把项目目录交给 agent，让它读 SKILL.md 路由
```
