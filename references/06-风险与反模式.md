# 06 风险与反模式：20 个坑和怎么提前绕开

> 适用阶段：全流程 ｜ 何时加载：范围失控、连续返工、进度落后、质量漂移、准备砍功能时 ｜ 上游：00 总览 ｜ 下游：回到对应阶段

## 这一阶段要回答的问题

1. 这个项目当前最可能死在哪一件事上？
2. 哪些"优化"其实是拖延或范围膨胀？
3. 如果只剩一半时间，砍什么、留什么？
4. 这个决定三个月后会不会变成返工？

## 输入

- `docs/00_立项书.md` 的"最大风险"与"不做清单"
- `docs/11_周报/` 最近 2–4 周
- `docs/09_变更单/` 全部
- 当前闸门输出与测试记录

## 步骤

1. **每月末花 20 分钟做一次风险扫描**：对照下面的风险矩阵，给每个命中项标概率（高/中/低）与影响（大/中/小）。
2. **只处理"高概率 × 大影响"的两项**，其余记录不行动。同时处理超过两项等于没有处理。
3. **把应对措施变成可执行动作**：写进下周周报的"待办"，不写"注意 XX"。
4. **连续两周同一风险命中**，升级为 D1 决策：进入变更单，选项里必须包含"砍范围"。
5. **每次砍功能后**：更新立项书的"不做清单"、资产清单、关卡总表，并通知所有线。

## 产出

- 更新后的 `docs/11_周报/<日期>.md`（风险与对策）
- 必要时：`docs/09_变更单/<编号>.md`
- 砍功能后：`docs/00_立项书.md` 的"不做清单"与 `docs/05_资产清单.csv` 的废弃项

## 风险矩阵

### 范围与需求

| 风险 | 早期信号 | 影响 | 对策 |
|---|---|---|---|
| 范围蔓延 | 每周新增点子 ≥2 个；"就加一个小系统" | 工期翻倍，完成度下降 | 砍功能清单排序；新点子先写进"以后再说"，不进本期 |
| 需求靠口头 | agent 做出的东西"感觉不对"但找不到依据 | 返工不可追踪 | 一律变更单；聊天里的决定 24 小时内落文档 |
| 规模估计过于乐观 | 单人计划 8 关 + 5 Boss + 技能树 | 永远做不完 | 首作按小品：3 关、5 敌人、1 Boss |
| 玩法没验证就扩内容 | P2 未过就开始做第 2、3 关 | 全部内容跟着一个不好玩的核心循环报废 | G2 之前只做 1 个灰盒关卡 |

### 美术与资产

| 风险 | 早期信号 | 影响 | 对策 |
|---|---|---|---|
| 风格漂移 | 第 20–30 张资产开始"不太像" | 整批返工 | 风格锚点 + 每批首张必审 + 色板/材质抽检 |
| AI 网格不可用 | 导入 UE 后拓扑烂、UV 重叠、面数爆炸 | 无法动画/优化 | AI 图生 3D 只当参考，必须重拓扑重展 UV |
| 资产爆炸 | 仓库 >20 GB，LFS 配额告警 | 协作卡死 | 只存导出件；源文件外部存储；每周 gc |
| 资产与清单脱节 | 有文件没登记、有登记没文件 | 找不到版本，重复生产 | 每天跑 `manifest check` |
| 材质实例爆炸 | 每个资产一套独立材质 | 包体大、性能差、改色困难 | 材质母材质 + 实例参数；资产清单限制材质槽 ≤4 |

### 技术

| 风险 | 早期信号 | 影响 | 对策 |
|---|---|---|---|
| 先光影后玩法 | 白模没跑通就在调 Lumen | 玩法返工时美术全废 | 严格按 P2 → P3 → P4 顺序 |
| 蓝图/C++ 双轨 | 同一逻辑两处实现 | 改一处漏一处 | 系统用 C++/组件，数值用 DataAsset，蓝图只做装配 |
| 过早 Nanite/World Partition | 小项目开全套高级特性 | 打包/性能/调试成本上升 | 默认关闭；确有需要再逐项开启并记录原因 |
| 性能翻车 | 白模就掉到 40fps | 后期无法优化 | P2 起每两周跑一次性能预算；先砍 draw call 与阴影 |
| 存档结构不可迁移 | 改字段后老存档坏 | 测试/上线后用户丢档 | 第一版就带 `SaveVersion` 与迁移函数 |
| agent 改坏工程 | 编辑器状态混乱、无法回滚 | 一天工作白干 | 分支 + 每日 commit + 禁区清单 + 操作前快照 |

### 协作与流程

| 风险 | 早期信号 | 影响 | 对策 |
|---|---|---|---|
| agent 自洽跑偏 | 交付"完成"，进游戏不是要的 | 隐性返工 | 交付单 + 证据 + 每周截图巡览 |
| 闸门形同虚设 | 为了赶进度跳过 `gate` | 问题滚到下一阶段放大 | 闸门失败只能修内容；记录每次跳过的代价 |
| 决策积压 | 待决策项 >3 个，连续两周没清 | agent 停工或自行决定 | 每周五固定清决策，超过 3 个说明任务切太大 |
| 文档与实现脱节 | 文档写 2.2m，游戏里 3m | 验收失效 | 数值单一来源 + 每周 `numbers check` |

### 发布与法律

| 风险 | 早期信号 | 影响 | 对策 |
|---|---|---|---|
| 商店页太晚 | 距上线 <3 个月才建 | 愿望单不足，首发无人 | 提前 6 个月建页；垂直切片后发 Demo |
| 平台审核不通过 | 缺隐私政策/评级/成就 | 延期 | 上线前 8 周跑 `gate release` 清单 |
| AI 素材授权不清 | 用了禁商用模型/字体/音频 | 下架/索赔 | 资产清单记录模型、来源、许可；关键资产人工重绘 |
| 崩溃无上报 | 玩家反馈"闪退"但无日志 | 无法定位 | 打包内置崩溃上报；Demo 前验证一次 |

## 反模式清单（20 条）

| # | 反模式 | 表现 | 后果 | 对策 |
|---|---|---|---|---|
| 1 | 文档写成愿望清单 | "画面要有呼吸感""手感要跟手" | 无法判定，验收靠吵 | 每条标准必须机器可查或人眼 3 秒可判 |
| 2 | 先量产美术再验玩法 | 200 个资产等一个没验证的核心循环 | 集体报废 | 白模先行，P3 才量产 |
| 3 | 逐项审核 | 每个资产都等用户签字 | 用户被拖死，进度停摆 | 前 20 个逐张，之后批次 + 抽检 20% |

| 8 | 一次性大重构 | "先把架构重写一遍" | 两周无可见进展 | 每次只改一个系统，保留可运行构建 |
| 9 | 跳过白模 | 直接搭成品关卡 | 空间/节奏/手感全错 | 灰盒 60fps + 盲测通过再换皮 |
| 10 | 光影先行 | 先调 Lumen 再验玩法 | 玩法返工，光照白做 | P4 才做光影氛围 |
| 11 | 资产无预算 | 8K 贴图、百万面模型 | 包体/显存/帧率崩 | 资产清单写死面数/贴图/LOD 上限 |
| 12 | 每张图单独 prompt | 没有风格锚点和模板 | 风格漂移 | 提示词宪法 + LoRA/参考集 |
| 13 | 直接使用 AI 网格 | 拓扑乱、UV 重叠 | 无法绑定/优化 | 重拓扑 + 重展 UV |
| 14 | 数值散落多处 | GDD、代码、表格各一份 | 改一处漏两处 | 06_数值表.csv 唯一来源 |
| 15 | 蓝图里写数值 | 数值藏在蓝图节点 | 无法批量调参 | DataAsset/DataTable |
| 16 | 过早优化 | 白模阶段抠 draw call | 本末倒置 | 先可玩，P4 再优化 |

## 砍功能协议

### 判断标准

按"砍了最不心疼"排序，而不是按"最难做"排序。每一项问三个问题：

1. 没有它，核心循环还成立吗？成立 → 砍。
2. 它能被现有系统的一个参数替代吗？能 → 砍。
3. 它会让资产量增加多少？>10% → 砍或延后。

### 砍的顺序（从先砍到后砍）

1. 收集要素、成就、图鉴
2. 支线剧情、NPC、对话分支
3. 第二种武器/技能树
4. 额外敌人种类（保留 3 种：普通/远程/精英）
5. 额外关卡（保留主线 3 关）
6. 高难度模式、二周目
7. 拍照模式、画廊、音乐鉴赏

**不能砍的**：核心循环、1 个 Boss、存档、设置、手柄支持、崩溃上报、基础教学。

### 砍完必须同步

- 立项书"不做清单"追加一条
- 资产清单把相关项标"废弃"
- 关卡总表删除对应关卡
- 周报记录"砍了什么、省了多少小时"

## 决策树：进度落后怎么办

```
落后 <20%：砍收集/支线，保持主线；不加人、不加班
落后 20–40%：砍 1 关 + 1 种敌人；把 Boss 改成精英怪
落后 >40%：范围减半，先做 1 关完整可玩 Demo；重新排期并告知预期
连续两周同一任务阻塞：任务切太大，拆成 ≤2 天的子任务
同一交付返工 3 次：标准不清，回 P1 补验收标准
性能不达标：先砍阴影/后处理/draw call，再考虑降分辨率
资产总是漂移：停量产，重做风格锚点与提示词模板
```
